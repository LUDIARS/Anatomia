# Source reference evidence

UX-AN-W2 requires review findings to retain concrete evidence rather than treating a missing call edge as proof of unused code. UX-AN-W3 preserves distinct source occurrences even when their normalized bodies share an Anchor ID.

`static-anatomy` owns `src/graph/reference-syntax.ts` and `src/graph/reference-evidence.ts`, with their tests in `src/graph/__tests__/reference-evidence.test.ts`. The existing domain membership declares both source and test paths before implementation. Syntax records are extracted while the file tree is alive and retained on `FileNode`; resolved evidence is a separate graph projection. `supply-verify` owns the classification in `src/review/build.ts` and regression cases in `src/review/__tests__/build.test.ts`. It never manufactures call edges, fan-in, complexity, domain ownership or entrypoints from these records.

TypeScript/JavaScript direct identifier calls (including module-level calls), `new` constructors, and identifier arguments passed as callback references resolve through lexical bindings and explicit relative named imports/re-exports. Same-file declarations and imported aliases must resolve to exactly one function occurrence. Shadowed parameters/locals, duplicate bindings, unsupported member dispatch, unresolved imports and ambiguous constructors provide no positive usage evidence. Callback references prove a source reference, not that the callback runs. Evidence includes kind, target anchor and source location and remains reviewable in the report. Self references do not prove an external caller.

Review excludes a fan-in-zero function only when a resolved reference targets it. Absence of evidence still means static reachability is unknown, never a dead-code assertion. This supplements the call graph; constructor dispatch through variables, wildcard exports, default and namespace imports are outside this initial contract. Cyclic re-exports stop without manufacturing a target.

Per-file cache format and graph cache versions change. Reused `FileNode`s without syntax metadata are reparsed, including retained-AST priors. This prevents old cache entries silently skipping the new analysis. Syntax is plain serializable data and must survive AST release and disk round trips.

Assignments and updates resolve to the owning lexical binding after declaration collection and conservatively invalidate its target across the file; writes in a child block never become a fictitious child-only shadow. Loop declaration bindings and optional/rest/destructured parameters shadow enclosing declarations. Flow-sensitive reassignment tracking is outside this contract.

Syntax version 2 records `uncertain` on the nearest runtime lexical scope for each parser ERROR/missing token (including unnamed punctuation). Resolution never passes through an uncertain scope; module exports also obey this rule. Unrelated scopes retain exact evidence. Errors wholly inside erased `type_annotation` nodes cannot hide runtime bindings and do not taint runtime scopes. Other recovery remains unknown reachability, not proof of unused code. Version-1 syntax priors are reparsed; file format 4, graph cache 5 and project output schema 6 invalidate earlier file-wide suppression results.

Graph cache localization preserves the same raw `CodeGraph` object when node locations and all resolved reference fields are unchanged. Another checkout or a changed node/reference location produces a clone and localizes the evidence without mutating the cached graph. Reference-only sources must participate even when they contain no function graph nodes.

Required regression cases: same-file constructor; named import alias for constructor; `map(reference)`; direct module-level call; cross-file test fixture call; shadowing by parameters, destructuring and block locals; duplicate local names; unresolved/external imports; no fabricated calls edges; AST release/cache round trip; same-root raw graph identity; cross-root and reference-only localization; occurrence-count complexity agreement.
